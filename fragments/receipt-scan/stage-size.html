Receipt scan: the camera picture size (Kitchie #750)

The report. Owner, 15 October 2026: a screenshot, no words (title: "Small footprint of the receipt"). It shows the live camera on a phone as a thin strip in a wide box: the picture is about 84 px wide in a 365 px box. On 15 October the owner said, by voice: "get it done, a few options, make some sensible decisions, build it straight into UAT." Everything marked Proposal below was decided by the agent under that instruction, not by the owner; overrule any of it.

Three sizes, side by side (live camera, 390 x 760)

Other heights, B: a 360 x 640 phone gets 218 px, a 390 x 844 phone 287 px, a 430 x 932 phone 300 px (the cap), a phone on its side (390 px tall) 150 px, as today.

Decisions (Proposal, RS-113 to RS-115)

  • RS-113. B is the default. The picture box is 34% of the screen's height, at least 150 px (so never smaller than today) and at most 300 px. On a 390 x 844 phone it is about 287 px, so a 9:16 camera frame is about 161 px wide, twice what it was. A is today's size. C leaves the list under 300 px on a 760 px screen.
  • RS-114. The handle still wins. Kitchie #754's drag handle (RS-96) and the remembered position replace this default exactly as before; the default is only what a first scan starts at, so #750 does not need #754 built.
  • RS-115. The picture is never cropped. It stays "contain" in a taller box (the receipt's edges stay visible); a taller box only means a bigger picture. Tablet widths (600 to 1023 px) share the rule. Desktop is unchanged.

Not done, on purpose: option 3 from the issue (a box that grows while the camera looks and folds to a strip when lines are read) is a layout jump and more script; the handle and the new default are enough for now. Wrong guess costs: a few pixels of list on a small phone; it is one CSS value.

For the build

One value: .ro-rl .rl-stage.lv-short{height:var(--qu-stage,var(--ro-stage,clamp(150px,34dvh,300px)))} (--ro-stage is only set by this page to compare A and C; the build does not set it). Nothing else loads or changes: no script, no new asset, no new token.
