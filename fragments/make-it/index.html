Make it: start making a planned meal

Mockup only, 15 October 2026. Kitchie issues #779 (the screen) and #781 (chat and screen follow one flow), both read only. Phone first at 360 and 390, light and dark, 44px targets; desktop for the Plan and Home. Every button below is clickable and the tap result opens the page that exists today. Sample data; nothing is saved.

What the owner said (Arjan, voice, 15 October 2026), decided
  • The label is Make it, not cook: it covers baking and prepping. “I need a button where we can start making whatever that’s on the plan.”
  • It is shown on a meal that is already on the Plan. A planned meal is never offered add-to-plan again.
  • Rename the existing Cook now to Make it everywhere (recipe flyout footer, cooking idea card, Home ideas).
  • Home must know whether the idea is planned for today: planned for today is just Make it; not planned for today is the existing Plan (add-to-plan) path, not Make it.
  • Reuse the existing Cook now flow; a new flow must say why. This page adds none: the tap opens the cook page for a saved recipe and the Cooking now screen for a made-up meal, both as they are.

What happens on tap Proposal (Kitchie #781, option 1)
  • Saved recipe: Make it opens the existing cook page (recipe/cook.html), the page Cook now opens today. No new screen.
  • Made-up meal (no recipe): Make it opens the existing Cooking now screen (ingredients first, web-cooking.ts), the one only the AI can start today. Its CSS is reused from ../plan-start-cooking/cooking-view.css.
  • Both: the tap first starts a Cooking now session through the same service the chat tool start_cooking uses, so the banner shows and chat and screen are one flow. This is #781 option 1, the one that needs only a route and wording. The mockup shows a one-line toast, then the page.
  • Why no new flow: everything above already exists. The only new thing is a web route that calls the existing start method. If the owner prefers #781 option 2 (the tap only links to the cook page) or 3 (a “making” state on the meal), the buttons here do not change; only what they call does.
  • Held meal: Make it stays and uses the held items; the hold ends when making ends. Never on a past day, in someone else’s view-only plan, or on Leftovers (as fragments/plan-start-cooking SC-P4). Shows on today’s and later days’ meals; something missing does not hide it.

Loads (DESIGN.md section 6, 6a)

Nothing new on any default path. Make it is one button in markup each screen already draws; its CSS (.mkbtn, about 1 KB) is lifted into the existing stylesheets. The tap result is in place of a navigation only for the app’s own cook page; the cook page and Cooking now screen load on tap, not before. This mockup page loads its own small files (make.css, lib.js, one script per screen) and the Plan phone reuses Kitchie’s plan.phone.css from plan-start-cooking. The iframes above are lazy.
