Recipe tags: the household’s own

Idea only, not for build

Live, clickable mockup for Kitchie issue #834. It exists so the Kitchie collaborators have something to talk around; drawing it approves nothing. Mockup only: nothing is saved or sent (tags you add are kept in this browser so the list and the recipe agree; reset the sample). Phone only for now.

The idea, as raised (owner, typed, 17 October 2026)

Recipes already carry tags, but they are set automatically when a recipe is saved or imported (“HelloFresh”, “rice bowl”, “quick”). The household cannot add its own, or filter, suggest or plan by them. The idea: let the household tag recipes, for example a meal type (“breakfast”), a calorie band (“300 cals”), an occasion (“treat”) or a focus (“protein”), then use the tags to find recipes, to steer suggestions and in weekly planning (“pick a breakfast”, “one treat a week”). Asked by voice the same day: “create mockups for that and follow our standard governance mode.”

1. Finding recipes by tag: two options

A. A tags strip agent recommends

The household’s tags sit on a second strip under All, Ready now, Starred, Under 30, always in view. Each tag toggles; several can be on. Only tags some recipe carries are shown. The count line says what is picked.

Trade-off: one tap, nothing to open, and the tags are discoverable; it costs one thin row, and past about ten tags the strip needs a sideways scroll. Open full size

B. A Tags sheet

One Tags chip at the end of the existing strip opens a sheet grouped by kind (Meal, Occasion, Focus, Calories), with how many recipes carry each. Pick several, then Show. The picked tags stay on a slim row under the strip, each with an ×.

Trade-off: scales to many tags and keeps the list screen as it is; finding by tag is two taps and hidden behind a chip. Open full size

Recommendation: A while the household has a handful of tags (the owner’s examples are four); B is the step up if the list grows. Both use the same matching rule (RT-P7) and both let search find a tag by name.

2. Tagging a recipe: two options

1. A tag row on the recipe agent recommends

Under time and serves, the recipe’s household tags show as chips with a + Tag chip. Either opens a sheet: the household’s tags by group, tap to add or remove (saved at once, a toast says what changed), and a New tag field with a group. Tags the recipe came with sit on their own line, lighter, as “From the source”; the … lets you hide one on this recipe.

Trade-off: tagging is a two-tap job while looking at the recipe, which is when people think of it; it adds a row to every recipe page. Open full size

2. Tags only in Edit

No new control. The Edit screen already has a Tags field (recipe edit mockup, owner 11 October 2026: tags are among the fields edited by hand). The recipe page lists the tags read only at the foot, with an Edit link.

Trade-off: nothing new to build on the page; tagging means opening Edit, and in Edit a tag change goes through the version flow like any other edit (see RT-Q2). Open full size

Choices the mockup made where the idea was silent (all Proposal)
  • RT-P1 One tag list per household. A tag is made once and reused on any recipe; every member sees the same tags. Wrong guess costs: if people want private tags, the list needs a Mine and Household split like Preferences option B.
  • RT-P2 A tag can sit in a group. Meal, Occasion, Focus, Calories (the owner’s four kinds) and Other. The groups drive the sheet layout and the matching rule. Wrong guess costs: if groups feel like admin, drop them and keep one flat list (option A still works).
  • RT-P3 Any member can tag and make a new tag. Same controls for everyone on Recipes (R-O5). Wrong guess costs: if new tags should be a household admin’s call (as household-level preferences are, D25 to D30), a member would only pick from the list.
  • RT-P4 The source’s tags are kept apart. Tags set automatically at save or import stay on the recipe, shown lighter as “From the source”, and can be hidden per recipe, never deleted. They are not in the household’s find list. Wrong guess costs: if the household wants Quick or Batch as their own, they would make the same word again (RT-P6 makes that one tag).
  • RT-P5 A list row shows up to two household tags, a picked one first, the rest as +n. Wrong guess costs: busy rows; the fix is tags only while filtering.
  • RT-P6 The same word is one tag, whatever its case (“protein” and “Protein”). New tags are up to 24 characters.
  • RT-P7 Matching: within one group any picked tag matches (Breakfast or Lunch); across groups all must (Breakfast and Protein). Wrong guess costs: someone expecting “all of these” inside a group sees more recipes than expected.
  • RT-P8 A tag sits on the recipe, not on a version. “Breakfast” does not change when the recipe is tweaked. See RT-Q2.
Open questions for the collaborators
  • RT-Q1 Calorie band: a tag or a fact? Recipe already stores per-serving nutrition (kcal) with its source. “300 cals” typed by hand can disagree with that figure. Option: offer “Under 300 kcal” as a filter worked out from nutrition where it is recorded, and keep a hand tag only where it is not. Wrong guess costs: two numbers that disagree on the same recipe.
  • RT-Q2 Recipe or version? The Edit mockup treats tags as part of a version (a change shows in the version’s changes). RT-P8 puts them on the recipe. One has to win before anything is built.
  • RT-Q3 Planning (not drawn). “Pick a breakfast” is a filter in the plan picker; “one treat a week” is a rule the planner acts on. A rule needs a closed vocabulary (Kitchie ADR closed-vocabulary-for-ai): the household’s tag list could be that vocabulary. Food preferences already have a frequency cap checked against recent meals (F-series); a tag could be its target rather than a new kind of rule.
  • RT-Q4 Suggestions. Should Cooking ideas and the assistant read the household’s tags (e.g. lean towards Protein), and if so is a tag a hint or a hard filter?
  • RT-Q5 Who curates the list? Renaming, merging and removing a tag the household no longer uses: where it lives (Settings or the sheet) and who may do it (RT-P3).
  • RT-Q6 Desktop. Not drawn. On desktop the tags would likely sit in the list column’s filters and the recipe panel; drawn only if the idea goes ahead.
What this loads (DESIGN.md section 6)

Default path: the Recipe tab’s own files plus tags.css and tags.js (both small). The household’s tag list would come with the recipe list (a few short words), so filtering is in place with no new request (section 6a). The picker and find sheets are built on tap. Nothing is fetched for tags on the recipe page beyond the recipe itself.

Checked at 360 and 390 in both themes. The strip chips are 36px tall, the same as the existing Recipes strip (recipe/list.html), below the 44px rule; that is the strip as it is today, not new here.
