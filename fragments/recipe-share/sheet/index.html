Share a recipe: create the link

Fragment, slice “sheet” of the recipe share feature. The job: send a recipe you are happy with to someone outside the household, with a link that expires and needs no sign-in. This slice is only the create flow, opened from the recipe's Share button. Where the button sits, the manage and cancel panel, and the recipient's page are other slices. Mockup only: nothing is created and every link is a placeholder (kitchie.example).

The owner's words voice, 13 October 2026
  • A recipe he is happy with can be shared with people outside the household through an expiring signed link, in spirit like the shopping-list link.
  • Recipients need no sign-in to view, and it works the same if they are signed in. Links are multi-use, not single-use, and they expire. The intent is growth.
  • Links can be renamed: give the name at creation and rename it later, like the shopping link.
  • Update, 13 October 2026: the sheet is option C. It shares “the usual” by default, and shows a version choice only when other versions exist. The sender can click to include an invite: single-purpose (only the first person to activate the link claims it), it sets up a new household and never joins an existing one, and it respects the member’s maximum-invites limit. The count lives where invites already live, not here.
Chosen: C (owner, 13 October 2026). The sheet shares the household’s usual version, shows a version choice only when the recipe has other versions, and carries an optional invite. A and B are kept below, marked not chosen.

Each option below is the real screen in a frame, so you can tap through it: the sheet, the expiry choices, the invite switch, Create, Copy, Share, Done and Esc all work. Phone is under 1024px (bottom sheet); desktop is 1024px and up (the Pantry's flyout). The Share button on the page behind is a stand-in so the sheet can be opened again; its real place is another slice.

CThe usual, with an optional invite Chosen

Shares “the usual” version. A version choice appears only when the recipe has other versions. One opt-in to include an invite.

  • Link name (prefilled), version (only with 2 or more versions), how long it works (24 hours, 7 days, 30 days), then the invite switch, then Create link.
  • Include an invite is off by default (a proposal). One line says what it does: one person starts a household of their own, only the first to use the link. The count, “2 of 3 invites left”, is the same wording and the same allowance as the links panel; nothing new is invented here.
  • At the limit the switch is disabled and says why in one line. The link can still be made without an invite.
  • The earlier custom date is dropped: three chips cover the realistic answers and a date picker for a link nobody counts days on does not earn its space.

BThe link already exists Not chosen

Opening Share makes the link at once with the defaults. Name and expiry become two rows you can change after.

  • Fastest for the common case: Share, Copy, Done.
  • Costs a link every time the sheet opens, even if it is never copied, so the manage list collects strays and any cap on links fills up. A real build would need to discard an unused link.
  • Changing the expiry of a link that already exists is a new rule to decide.

States of the chosen option

Every state of C has its own link: invite off, invite on, limit reached (switch disabled with its reason), a recipe with one version (no picker), created, created with an invite (an invite line under the link), copied, error (Create failed, nothing made, no invite used, Try again) and after Done. The last link makes the first Create fail. A and B keep the earlier states (add &s=default|created|copied|error|done).

Performance

The recipe page loads nothing for sharing: in the build the sheet's code loads when Share is tapped. In this mockup phone and desktop each load only their own pair (phone.css and phone.js, or desktop.css and desktop.js). The link is made in place and the result lands in the same sheet, with no navigation (DESIGN.md section 6a).
