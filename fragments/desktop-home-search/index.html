What this does

  1. Idle is the settled Dashboard, unchanged: Cooking ideas (the lead is today’s plan, else the top idea), Other ideas, On the way out and Running low, This week in the gutter. The Dashboard / Compact toggle is gone. Nothing new is added: no chips, no status pills, no near-miss cards, no Plan tonight button.
  2. Searching starts at the second character, with no Enter. A dropdown sits directly beneath the bar (6px gap, the bar’s width). The cards, the rail and any open flyout fade to 14% and cannot be focused, so the dropdown is the one answer. This week does not recede (owner, 22 Oct 2026): it stays at full strength, in its place, and its days stay clickable. Nothing moves or reflows (DESIGN.md 6a). Collapse in the controls shows the other reading of “fade, dim or collapse”.
  3. The way back: Esc clears the field and idle returns at once (focus stays so you can type again); a second Esc on an empty field leaves it. Deleting the last letter or the field’s own clear (x) does the same. Leaving the field by click or Tab hides the list but keeps the words; focusing it again shows it.
  4. Picking keeps the existing behaviours: a recipe opens the 400px flyout lane (decision 290 without the Compact-only parts), a pantry item opens the item panel (291). The list closes, the words stay in the box, nothing is cleared; closing the flyout (Ctrl Esc or its x) returns focus to the box without reopening the list.
  5. Context, not just names. A recipe also matches by its ingredients (“chick” finds the satay and the tacos that use chicken). Each row says why it is here: uses the chicken thighs going off tomorrow, needs laksa paste, coconut milk and rice noodles, Priya avoids peanuts, planned Thu. A line at the top of the list says what the ranking is for (tonight, who is eating).

Open questions, and what a wrong guess costs

HS-Q1 Should the single Home be leaner? Search now does the finding, so the Other ideas rows (two recipes you could also search for) are the first candidate to go, then the stack under it, giving idle one lead and nothing else. Recommendation: keep it as it is for this build; revisit after he has used it. Cost of a wrong guess: none either way to the search; removing rows later is a delete, adding them back is a revert.
HS-Q2 Dim or collapse behind the list. Recommendation: dim (HS-P3). Cost: a CSS class.
HS-Q3 Where does the contextual ranking run? (a) the client over an index read once on first focus (instant, but ships every recipe’s ingredients and the stock; stale after a change); (b) one debounced server call per keystroke returning the groups (always fresh; every letter is a request, and Recipe and Kitchie both answer it); (c) names instantly from a client index, the context (missing, use-by, avoid) added when the server answers (fastest to feel, hardest to build). Not decided here. Cost of a wrong guess: (a) ships data and logic that must match the server’s rank; (b) can feel laggy; (c) rows change under the cursor. The mockup’s rank() is pure so any of them can host it.
HS-Q4 What does a shopping-list result do? Options: go to Shopping with the row in view (drawn), or a flyout in the lane with Remove, Edit quantity. Cost: the first leaves Home mid-task against the in-place principle (6a).
HS-Q5 Start at 1 or 2 characters? Recommendation: 2 (HS-P2). Cost: a constant.
HS-Q6 Is a recipe left out for a person shown, hidden, or shown only when the words name it? Recommendation: shown last, dimmed (HS-P7). Cost: see HS-P7. A related, preferences-level question the Compact notes already carry (CH-Q5): may a person be left out for one night from here?
HS-Q7 Is 8 rows right? Cost: a constant.
HS-Q8 (follow-up) With a flyout open and the owner then types, This week is covered by the dimmed flyout. Options: (a) as built, the flyout dims and covers the gutter; (b) typing closes the flyout (like Esc on it), so This week shows; (c) the flyout hides while typing and returns on Esc. Recommendation: (a) for now, since you said nothing else changes; (c) if you want This week always visible. Cost: a small rule in search.js; (b) loses the open recipe.
HS-Q9 (follow-up) Narrow widths. This fragment draws the 1224px frame at a fixed size (the page scrolls sideways inside the figure when the window is narrower); it has no responsive layout and no tucked-away This week, so there is nothing to carry the new rule into at ~1100. The tuck-away (Small 1024 and the 1240px breakpoint in the Desktop handover) lives in the desktop Home build, not here. Recommendation: when it is built, This week stays active while searching at every width it is shown; where it is tucked away it stays tucked away (nothing is forced open). Cost: wrong guess is a build rule.

What loads

  • Default path (idle Home): theme.css, theme.js, home.css, home.js. No images, no fonts (emoji are text). Nothing about search results.
  • First focus of the bar, or first keystroke: search.css and search.js (the dropdown, the ranking, the sample index). In the build this is the moment the one search read happens (intent-based, DESIGN.md 6); nothing is fetched on page load and nothing is fetched per scroll.
  • First result picked (or first row opened): flyout.js. In the build: the one recipe or item read, only then.
  • Viewport-specific files only. This folder is desktop (1024px and up) and shares nothing with the phone files; the phone search is fragments/pantry-search/. It loads only ../../theme.css and ../../theme.js from outside the folder.

For the implementation

  • Copy home.css and search.css, and the markup home.js and search.js write; list each difference in the PR (AGENTS.md). Class names are desktop-home’s plus .sw .ctx .rk .mt .foot .fly and the searching state class on the desk. Sample names live only in the two scripts.
  • Accessibility is built in: the input is a combobox, the list a listbox of options with aria-activedescendant, a live region announces the count, the receded areas (not This week) lose pointer events, and every row is 48px high.
  • Check: node tools/desktop-home-search-check.mjs (add --shots=DIR for screenshots).
