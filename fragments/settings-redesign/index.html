E. Curated front, pinned shortcuts, search for everything

recommended default

The hybrid. Settings opens on a search box, then Shortcuts (one area, made of pinnable segments: Looks, and Text size), then five rows: Looks, Preferences, Household, Kitchen setup, Assistants. Nothing else is on a page. Everything else, including the knobs A would have removed (rows, motion, the bell, Reset) and rarely used household items, is found by search, which says what each result affects, where it lives and what it is now, and lets simple ones be changed in the result itself. Try it below: press an example, or type in the box on the phone or the desktop window, and use /, ↑ ↓, Enter, Esc.

  • Pin model. Pin a segment with its pin button (on its own page, in a search result, or the dashed “Pin” chip in Shortcuts). Pinning adds a shortcut tile; it moves nothing and loses nothing, so unpinning is always safe. Pin both, one or none to see each state; the gallery shows the empty one. The owner decides what is pinnable; there is no “pin anything”.
  • Text size. Match my phone (default, Kitchie adds nothing), Standard, Larger, Largest. It scales the whole frame and all three sample screens below: Home, Pantry, Shopping. It replaces Item name size (Pantry only, #1089); search for the old name still finds it. Rows (Standard / Names only) replaces the four row switches and reaches the Pantry and Shopping lists. Try “Pretend phone text: Large” in the bar with Match my phone, then with Standard.
  • Reset to defaults is found by search only (“reset”, “undo changes”, “start over”). It resets this device’s display settings, never pinned shortcuts or household data, and says so. Where it goes in A to D is in the ledger.
  • Loads by default: this page, settings-redesign-e.js and .css. Deferred until search is used: search-index.js (the index and every synonym), fetched on first focus, typing, an example press, or when the gallery nears the viewport. Nothing is stored.

Try a search

Search, in every state

Each card is the same search drawn for one kind of query. The controls in them are live and share one state with the phones above. Result rows are two things: phone (stacked: name, why it matched, what it affects, where it lives and its current value, then the control) and desktop (the same, in two columns with the control on the right).

How a result is ranked

  • Order of evidence: exact name (100), an old name or a name containing every word (92), an exact synonym or phrase (90), a phrase inside a longer sentence (72), then word by word (name 30, synonym 22, a prefix a little less, a one-letter-off word a little less again, the description and place 6). A result needs at least half of the words to hit. Advanced results sit 4 points lower, so an ordinary answer wins a tie. Then the curated order breaks ties.
  • Typos: a word nobody has ever used is replaced by the nearest word someone has (one edit up to six letters, two beyond; a swapped pair counts as one). The page says what it did and offers the exact search.
  • Small words are ignored (the, my, to, how, make, change, turn, off). Plurals are folded (“animations” is “animation”).

A. Just the essentials

leanest fallback

Settings stops existing; Looks has three controls: Theme, Light or dark (this is Kitchie #1088, mockup#285, folded in), Emoji. Text size, motion and dark at night belong to the phone and Kitchie follows. Row detail is not a preference, because the job decides what a row shows (DESIGN.md section 1). The household bits stay where the menu already has them. Try “Pretend phone text: Large” in the bar: every screen grows, which the in-app size never did. With two assistants connected a fourth card appears; with one it is never asked.

Gone: text size, reduce motion, show spot, amount, use-by, activity, compact, Reset, the legacy theme field, the Settings overview page, the Settings row on the menu, the second Install, second Sign out and second copies of Categories and Locations. Cost: a person who really wanted larger text must set it on the phone. Effort: mostly deletion plus one check that type is rem-based; no data migration, because unknown stored keys are already dropped on read.

B. Grouped by job, More for the rest

Keep a Settings front door, but organise it by job: How it looks, How it behaves, My household, Assistants. Each page leads with the two or three things people change, the rest is under More. The four row switches become one Rows choice (Standard, Compact, Names only), text size becomes a whole-app Larger, motion follows the phone, and the stock-check dials from Preferences get a front door but are not changed. Stays closest to today; the most new UI of the four; one more tap to anything (theme is four taps from Home).

C. Search first

One search box, six common things, and everything else found by typing: dark, text, quiet, sample. Every knob stays (so the Pantry-only size stays too), which is exactly the cost: a search index of 27 entries and their synonyms to keep true. Good if the set of settings grows; wasteful for a handful. Press / on desktop. Try “dark”, “text”, “zzz”.

D. In context, with a thin page

A setting lives where it is used. Aa on the Pantry list (desktop: View beside Sort) holds text size and which details a row shows, labelled This list so it never promises the whole app. Theme, Light or dark and Emoji sit at the top of the avatar’s profile menu. The Settings page that is left holds only what is not about looks: Kitchen setup, Household, Assistants, Install, the CSV. Honest about scope, but it builds a little menu for every list, and repeats the Pantry-only limit on each. Press Esc to close the popover.

Recommendation

Take E. It is the owner’s own hybrid: a small, opinionated front door (A’s list), one pinnable Shortcuts area (Looks, Text size), and a search good enough that nothing needs a page. It keeps every fix A made (no knob that over-promises; text size is whole-app and visible on three screens) and does not delete the knobs A removed: eleven of them live in search, flagged Advanced. Cost: the search index (52 entries and their synonyms to keep true) is a new feature, and so are Shortcuts. A remains the leanest fallback if search is cut; D’s rule still applies to anything he insists on keeping near a list.

Answers: Reset to defaults is found by search only and never touches pins or household data. Text size reaches the whole app, in four steps. Item name size goes; its name still finds Text size. Pins: two segments now, no cap needed (propose a cap of four when more exist).

Open questions SR-Q1 to SR-Q30, each with a recommendation and how it was checked, are in the knowledge note. The ones that block a build: whether “Standard” text size is possible on Android (SR-Q22), what search may cost to build and keep true (SR-Q26), and whether to ship the whole index at once (SR-Q27).

Notes for the build

  • Option E adds settings-redesign-e.js, settings-redesign-e.css and the deferred search-index.js. Its markup reuses the same class names; its own are .etile .eshort .pinb .eadd .sr .sr-ctl .escr. The index file is plain data (id, label, synonyms, affects, scope, value, advanced flag, destination) that the app would generate from its setting definitions.
  • Markup uses the app’s own class names (.mtop .menu.card .srow .swt .seg2 .tpick li[data-row] .name .meta .due) and tokens from theme.css; the data-size, data-compact and data-hide rules are layout.ts’s, scoped to the frame (.fr) instead of html. The mockup has ten look files; the app has Kitchie automatic plus nine.
  • Mode here switches Kitchie Night and Day only; all ten looks in both modes are in mockup#285 (Kitchie #1088), which this page does not redraw or contradict.
  • The phone-text aid scales the frames; on a real phone the browser does this to the whole page. Not tried on a device.
  • Loads by default: this page, theme.css, theme.js, settings-redesign.css, settings-redesign.js. Deferred: the ledger’s data.js (when the ledger nears the viewport), and a theme’s own file when it is picked. Nothing is stored. Desktop frames scroll sideways inside their own box; the page does not.
