Recommendation

A, one surface (on UAT now). It is the mockup’s recommended plain chevrons, the least to learn, and every card then reads as one family with the hero. If urgent sections are missed in real use, move to C, edge bar before B: a bar is a shape, so it still reads without colour, and it adds no second surface. B is kept only for the record.

Decisions and open questions

  • HC-D1 (built, a regression fix). One card surface for the hero and the three sections: var(--surface), 1px var(--border), var(--r-card). The hero’s lead is a hairline on var(--bg); no heavy outline on the phone.
  • HC-D2 (built). Word pill at the right of the title row, 11px; the bare count is hidden while the pill shows.
  • HC-Q1 Which urgent treatment: A, B or C? Recommendation A now, C if needed. Cost of a wrong pick: A too quiet (an expired item missed), B a second card surface, C one more mark. All three keep the words, so none is colour alone.
  • HC-Q2 Should the hero keep “See all”? The build has it (behaviour kept); the mockup hero has none. Recommendation: keep.
  • HC-Q3 The blurred header. Needs the owner’s phone: is it the installed app’s translucent status bar?
