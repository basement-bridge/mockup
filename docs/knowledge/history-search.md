## What the screen is

- **Entry (H4, H6, H8, unchanged):** "Since you were last here", three calendar days with activity at most, tick (marks caught up) and X (leaves, does not mark it). Summary counts are of the loaded rows only. A person in the summary opens that person's changes (`actor`), with a way back. Rows by an event with no member are counted but not a link (no parameter selects them, Q5).
- **Tabs:** My activity (`actor=me`) and the other person (`actor=<id>`) or Others (`actor=others`). Unchanged from H13.
- **After the X (H7a, H8, H15):** recent history, one calendar day with activity per load (`days=1&tz=`), newest first, quiet days skipped, no ceiling, no button. Phone: the filter sheet opens over the list (Pantry's Filters sheet classes: pick a group, then one choice). Desktop: the filter panel in the lane.
- **Filters (every one a Platform query parameter, single-valued):** When (`from`), Who (the tab, `actor`), Area (first part of `kind`), What happened (`kind`), App (`product`), Touches (`affects`). In context from an item adds `entity_type` and `entity_id` as a removable token ("This item"; needs `product`). Each group name shows its parameter under Mockup notes.
- **A row:** the skeleton the event always has (who, when, app and area) plus the kind's template output (`HM.render`). No template published, or the evaluation fails: the generic row "Sam made a change in Recipe". Template being fetched: skeleton row (who, time, app; empty body). Platform down: shown as down, never as empty.
- **Open a result (H5):** a bottom sheet on phone, the lane on desktop (replacing the filter panel, back arrow returns). Content: who and when and app from the skeleton, then the template's output including its `detail` lines, and a link only where the template defines one to a route the product registered. Nothing else. A generic row opens a generic detail.
- **Preview control (mockup only):** person, household size, catch-up or recent, last visit (Wed is older than the cap), template registry (published, fetching, nothing published), affects (filled, or as Kitchie writes it today: none), no-member events in Others (Q5), keyword box (Q1), mockup notes on and off.

## What the default path loads and what waits (`DESIGN.md` section 6, 6a)

Loads: the page, `theme.css`, `shared.css`, `option-d.css` (shared classes; 19 KB), `search.css` (about 3 KB), `model.js` (about 12 KB, the stand-in for Platform; the build replaces it with the calls) and `search.js` (about 25 KB). One feed call for the open tab: the catch-up's three days, or the newest day. Waits: the other tab; older days (one per call, only when the end of the list scrolls into view); the filter choices (registry call on opening Filters); a template (fetched on first sight of a kind, cached); the detail (rendered from the row already loaded, no new request; the template link is only followed on tap). Everything lands in place: tabs, filters, days and the detail swap content without navigation. Phone and desktop share one script (CSS-first, DESIGN.md 7); the lane exists only from 1024px.
