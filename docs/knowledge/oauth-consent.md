# Connect an assistant: the consent page (Platform's OAuth screen in Kitchie's look)

Mockup: `fragments/oauth-consent/` (`?p=kitchie|recipe`, `&a=claude|chatgpt|long`, `&env=none`, `&dev=1`). Owner request, Monday 12 October 2026 (task brief): rebuild Platform's OAuth consent page (`/platform-uat/oauth/authorize`, "Connect an assistant") so it matches Kitchie's look and feel; one consent page for both Kitchie and Recipe connections; follow the person's theme without a flash; phone and desktop. Today it is an unstyled page: a heading, one paragraph, two plain buttons and a safety line.

The owner's words that matter: "same look and feel as Kitchie", "one logo everywhere, brand bar on every page" (Kitchie v0.12.21, issue #145), "one consistent consent page for both Kitchie and Recipe", "keep the existing safety wording", "no hints or upsell for products not enabled" (Platform D6), "apply the theme before first paint", "viewport-specific code goes in its own file".

Status: **mockup, awaiting the owner**. The built page (Platform `apps/portal`) is built to `uat` from this mockup and flagged (see Open questions).

## What the page is (what a person is here to do)

An AI assistant has sent a signed-in member here to ask: may it act as me in this product? The job is a safe yes or no, so the page leads with who is asking and what for, then what agreeing allows, then the two buttons. Nothing else competes.

## Decisions (numbered; the first nine come straight from the owner's brief, the rest are **Proposal** where the owner was silent)

- **C1 One page, two products.** Same markup and CSS for Kitchie and Recipe. Only the product name, its icon tile and the words that name it change (`data-product` on `main`). Owner brief.
- **C2 The logo is Kitchie's, always.** The brand bar is the one Kitchie logo (fridge glyph, wordmark "Kitchie", then the environment in brackets when Platform has one, as Kitchie draws it). It is the same for a Recipe connection: "one logo everywhere" and "Kitchie is the only UI a person sees" (Platform decision, 6 October). **Proposal** for the Recipe case: the owner said one logo, not what a Recipe-only household sees.
- **C3 Names the product, the assistant and its origin, the member and the household.** A four-row facts card: Assistant (name and, under it, the host the assistant's own verified document gave), Connecting to, As, Household. The headline and the first sentence also name assistant and product. Owner brief.
- **C4 What access is granted, in four short icon rows under "If you agree":** it can read and change what you can in the product; it works for your household (named); it stays connected until you disconnect it; it will not see your password or your sign-in. These are the existing sentences, split, nothing added about what is allowed.
- **C5 How to disconnect, said on the page:** "You can disconnect it at any time from your connected assistants", the last words a link to Platform's connect page (the list that already has a Disconnect button). Owner brief. **Proposal** for where it points (see Q-C2).
- **C6 Safety wording kept exactly:** "Only agree if you started this from the assistant yourself." as the small line under the buttons. Owner brief.
- **C7 Buttons are not sticky and come after what is being agreed to.** Kitchie's sign-in screens pin the primary button to the bottom; for a consent screen that hides the last rows behind the button on a short phone. Primary "Agree and connect" (52px, accent), ghost "Cancel" (underlined text, 44px). **Proposal.**
- **C8 The assistant's tile is its first letter, never its picture.** The assistant's name comes from a document the assistant's own server serves, so it is untrusted text; its logo is never loaded. **Proposal** (a security choice; the owner can ask for logos).
- **C9 Nothing about any other product (Platform D6).** The page names the one product being connected and no other, enabled or not. Owner brief.
- **C10 Theme.** The page follows the person's own theme when Kitchie's choice reaches it, else the phone's light or dark. Kitchie's real storage is **a cookie, `kitchie_theme`**, set by Settings with `Path=<product prefix>` (`/kitchie-uat`), not localStorage; the only localStorage key Kitchie has, `kitchie.settings`, holds `theme: "auto"` and nothing else. The built page reads the cookie on the server, so the theme is in the first paint with no script. The mockup's own theme button uses the mockup's `theme` localStorage key and is demo chrome only. **See Q-C1: a cookie scoped to `/kitchie-uat` is not sent to `/platform-uat`.**
- **C11 Same tokens, same fonts.** Every colour, radius and type size is a Kitchie token (`--bg`, `--surface`, `--border`, `--fg`, `--muted`, `--accent`, `--on-accent`, `--sage`, `--head`, `--r-ctl`, `--r-card`); no raw colour in the page CSS. Fonts are Kitchie's own two files (DM Sans body, Bricolage Grotesque headings, OFL), `font-display:swap`.
- **C12 One column on phone and tablet (34rem, the width Kitchie's sign-in card uses); on desktop (64rem and up) the same column sits in a bordered card.** The desktop framing is its own file (`consent-desktop.css`, linked with `media="(min-width:64rem)"`), so phone and tablet never carry it. Owner standing rule, 10 October 2026.
- **C13 Long text never breaks the page.** A long assistant name, host, member or household wraps (`overflow-wrap:anywhere`); checked with `&a=long` at 360px.
- **C14 Reduced motion.** The three dots between the tiles are the only animation; they stop with the phone's reduced-motion setting and with Kitchie's "calmer motion" setting.
- **C16 The development sign-in warning.** While a deployment has test sign-in on, Platform shows one loud notice at the top of every page (`&dev=1`): an accent-bordered box on the surface, bold first line. It sits above the picture so it cannot be missed and is absent in production. Added 12 October after the build found the first mockup left it out.
- **C15 Other Platform pages** (sign-in, home, connect, token, notices) take the same brand bar, tokens, fonts and buttons through the shared page shell, but keep their content. Only the consent page gets this new composition. **Proposal.**

## What the default path loads, and what is deferred (DESIGN.md section 6)

Default path: the page's HTML with one inline stylesheet (tokens, the page's rules) and, for a person who has chosen a theme, that one theme's tokens inline (about 250 bytes). Two font files (about 78 KB together, `swap`). Nothing else: no script, no image, no icon file (icons are inline SVG). Deferred: the desktop stylesheet loads only at 64rem and up (its own file); no theme picker (themes are chosen in Kitchie's Settings).

## Open questions (what a wrong guess costs)

- **Q-C1 Theme storage does not reach Platform.** Kitchie writes `kitchie_theme` with `Path=/kitchie-uat` (and the production prefix). A browser sends a cookie only under its path, so `/platform-uat/...` never receives it, and the brief's "same origin so it is shared across paths" holds for localStorage but Kitchie does not keep the theme there. Options: (a) Kitchie also writes the cookie with `Path=/` (a one-line change in Kitchie's `settings-page.js` and `theme.ts` scope; Recipe would need the same to share a theme); (b) the theme is also copied to a localStorage key that Platform reads with a small inline script (needs a CSP change and a flash-free script; a second source of truth); (c) Platform follows the phone only. The built page works with (a) as soon as Kitchie sets the path, and falls back to (c) until then. Cost of guessing wrong: a person who picked Marmalade sees Kitchie's default on this one page.
- **Q-C2 Where does "disconnect" live for a person?** Today: Platform's connect page. Kitchie's Me screen also has "reset/relink AI". If the owner wants the link to point into Kitchie instead, it is one href.
- **Q-C3 Recipe-only household.** The bar says "Kitchie" even where only Recipe is entitled (C2). Say if that should be a neutral wordmark.
- **Q-C4 Fonts and the Content-Security-Policy.** Platform's pages carry `default-src 'none'`. Fonts and the desktop stylesheet need `font-src 'self'` and `style-src 'self'` and two small static routes on Platform. That is a security-surface change; the built page is flagged for the owner's confirmation.
